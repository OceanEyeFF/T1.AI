# 规则检查技能

## 概览

本技能实现 `WorktrackScope.Verify` 算子的 `policy` lane（策略校验面），对应 Harness 控制回路中的**收集证据**阶段。它负责收集规则与治理维度的证据，为 `gate-skill` 的 policy-gate 提供输入。它与 `review-evidence-skill`（implementation lane）和 `test-evidence-skill`（validation lane）共同构成 Verify 的三个正交校验面。

当 `Harness` 已经有一个活动中的 `工作追踪`，并需要在 `工作追踪范围.验证中` 中完成一轮限定范围 `规则检查` 时，使用这个技能。

这个技能会把当前规则/治理检查封装成一个限定范围的 `通用高能力模型` `子代理` 任务，收集面向策略的证据，并返回供后续关卡使用的结构化交接结果，而不是自己裁决最终 `策略关卡`。

## 何时使用

当当前问题不是"这个工作追踪能否通过关卡"，而是"本轮已经掌握了哪些规则/治理证据"时，使用这个技能：

- 检查当前差异是否仍停留在已声明的范围与分层规则内
- 验证被触及的表面是否触发了必须同步的治理项
- 运行或检查本轮最小必要的规则/治理检查
- 为 `关卡证据` 收集路径、结构、文档同步与边界证据
- 把策略发现、缺口与延期检查返回给 `Harness`

## 工作流

1. 载入当前差异表面所需的最低限度 `工作追踪范围` 与治理产物。
2. 为一轮限定范围的 `通用高能力模型` `子代理` 构建一份 `规则检查任务简报` 和一份 `规则检查信息包`。
3. 判定本轮实际涉及的治理层面：
   - 根目录或路径分层
   - 文档或必需同步义务
   - 技能或模板边界规则
   - 分支或审查流程治理（如果工作项依赖它们）
4. 只运行或检查本轮最小适用的检查与规则来源。
5. 将结果分为：
   - 已收集的策略证据
   - 违规或范围泄漏
   - 缺失证据
   - 推迟或不适用检查
6. 返回一份固定格式的 `规则检查报告` 加一份 `策略证据交接`。
7. 在最终关卡判定之前停止。

## 规则检查约定

每次运行这个技能时，都使用同一套限定范围约定格式。

### 规则检查任务简报

- `触发条件`
- `目标`
- `工作追踪`
- `节点类型`
- `适用 gate_criteria`
- `变更表面`
- `范围内`
- `范围外`
- `约束`
- `必需检查`
- `完成信号`

### 规则检查信息包

- `当前工作追踪状态`
- `节点策略`
- `相关差异`
- `已变更产物`
- `参与中的治理规则`
- `可用验证结果`
- `已知风险`
- `所需上下文`
- `开放问题`

### 策略证据交接

- `策略证据项`
- `违规或缺口`
- `必需同步项`
- `推迟检查`
- `审查指令`
- `建议后续跟进`

## 硬约束

遵循本包内最小公共约束 C-1 至 C-7：C-1 只在声明的 Scope/Function 内操作；C-2 只有授权的 SetGoal/ChangeGoal/Close/Refresh 路径可变更控制状态，其余技能返回结构化输出；C-3 先生成完整报告再提取 Control Signal，重复上下文用 artifact 引用，空字段用 N/A；C-4 不跨越 Observe/Decide/Init/Dispatch/Verify/Judge/Recover/Close 的角色边界；C-5 只消费已批准上游产物，不凭空发明验收或恢复标准；C-6 缺失证据必须显式暴露，不能当作成功；C-7 保持限定范围，避免不必要的全仓重发现。Source-side authoring trace: docs/harness/foundations/skill-common-constraints.md。

- 规则的输出范围只能限定在当前差异表面与治理产物之内；完整代码仓库审计的行为禁止出现在策略证据的输出中。
- 仅当审查证据或测试证据被明确当作输入引用并记录来源时，将其视为规则检查证据才合法；否则必须将其排除在策略证据之外。
- 当被触及路径明显触发了必要同步义务时，唯一合法行为是将其显式暴露在 `必需同步项` 中；隐藏同步义务的行为必须返回 blocked。
- 输出只能分别呈现违规、缺失证据与推迟检查三个独立段落；把三者混成一段模糊摘要的行为禁止出现在策略证据的输出中。

## 预期输出

使用这个技能时，产出一份至少包含以下章节的 `规则检查报告`：

- `规则检查触发条件`
- `规则层面评估`
- `已运行或已检查项`
- `已收集策略证据`
- `违规与缺口`
- `推迟或不适用检查`
- `返回 Harness`

结果中至少应包含以下字段或等价表达：

- `子代理模型`
- `工作追踪`
- `变更表面`
- `已运行检查`
- `已通过检查`
- `策略证据项`
- `已发现违规`
- `缺失证据`
- `必需同步项`
- `推迟检查`
- `已准备好进入关卡输入`
- `建议后续跟进`
- `如何审查`
