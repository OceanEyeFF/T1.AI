## Purpose

当前阶段不再把 `alpha_score` 作为研究重点。Milestone 目标是让主线 `3d/5d/10d` 三个预测头的可信度可以被一致、可复跑、可防伪地评估：预测分数高的股票，在对应 horizon 后是否真的相对更好；若看起来更好，是否能通过 random-label、行业 / 市值中性化、同窗报告契约和 smoke 级同窗比较。

## Scope

### In Scope

- `pred_3d` / `pred_5d` / `pred_10d` 三个预测头的单独可信度评估。
- random-label 防伪检查的最小 CLI / 报告契约。
- 行业 / 市值中性化评估门禁的最小可用实现或清晰接口约束。
- XGBoost 报告契约补齐，使其可被 A2 协议检查消费。
- LSTM / XGBoost 在同一 OOS 窗口、同一报告结构下的 smoke 级比较。
- 三头预测验收报告：逐 horizon 记录 IC / RankIC、月度稳定性、Top-vs-Bottom 或等价排序证据、防伪结果与失败原因。

### Out Of Scope

- `alpha_score` 优化、晋级或默认启用。
- 决策模型 C1/C2/C3、真实交易逻辑、目标仓位、订单生成或生产调度。
- 长耗时全量训练、真实模型推广、release、tag、push。
- `1d` 日内模型训练或外部 provider live pull。
- 以 quick8 小样例或 calibrated 技巧直接证明模型可用。

## Acceptance Criteria

- 每个 Worktrack 必须同时写出“抽象目标、具体操作、对模型影响、对量化影响、验收方式”，便于非金融专业背景的 programmer 评估。
- `pred_3d` / `pred_5d` / `pred_10d` 必须分别评估，不得只用聚合分数替代三头结论。
- 如果 random-label 或中性化检查失败，必须把对应预测头标记为 no-go 或 continue-research，不得包装成可用信号。
- XGBoost 与 LSTM 的比较必须使用同一 OOS 窗口、同一报告协议和同一主要指标口径。
- smoke 级评估不能被解释为模型性能突破；它只证明评估链路能运行。
- 最终报告必须能回答：预测头高分股票在对应 horizon 后是否相对更好，以及失败原因更可能来自数据、标签、特征、模型还是评估契约。
- 不允许在本 Milestone 内优化、晋级或默认启用 `alpha_score`。
