# 主题缺口索引

本文档只记录大方向缺口，不拆到任务和实现细节。

使用方式：

- 先按主题定位：`交易` / `数据` / `训练`
- 再判断缺口主要落在哪一层：`overview` / `modules` / `interfaces` / `research`

## 1. 交易主线缺口

### Overview

- 还缺一份更明确的“研究输出如何转成可执行交易动作”的总叙事。
- 交易、风控、调度三者的优先级关系还没有在项目级文档里讲透。

### Modules

- 组合决策、风险控制、执行反馈这三个模块的边界还不够显式。
- 生产调度和回测调度之间的关系还没有统一成一套模块视图。

### Interfaces

- 订单、持仓、成交失败、风控触发这些对象的统一接口还不够完整。
- 交易诊断输出虽然有规则，但还没有沉淀成稳定的报告契约。

### Research

- 成本、换手、成交阻断对模型价值的影响还缺统一研究入口。
- “预测有效”到“交易有效”的研究转换标准还需要继续固化。

## 2. 数据主线缺口

### Overview

- 还缺一份“项目长期数据战略”说明，明确哪些数据是主干、哪些只是增量。
- 数据治理、版本管理、可追溯性在项目级仍偏分散。

### Modules

- 数据接入、快照、特征加工、回放这几层的职责还可以再收得更清楚。
- 行情、新闻、公告、基本面等模块之间的协同边界还不够统一。

### Interfaces

- 除日线主契约外，文本事件、基本面、未来分钟级数据的接口定义还不完整。
- 数据版本、快照标识、可用时间字段还没有形成统一的最小接口集合。

### Research

- 数据源切换带来的覆盖率、质量漂移、标签影响还缺稳定对比框架。
- 另类数据进入主流程前的验证标准还不够统一。

## 3. 训练主线缺口

### Overview

- 还缺一份更清晰的“训练在整个系统里的角色边界”说明。
- 训练、评估、上线候选之间的关系，目前更多靠研究文档理解，项目级总结还不够。

### Modules

- 训练流水线、模型注册、重训调度、产物落盘之间的模块边界还可以更清楚。
- 离线训练和线上重训触发之间还缺统一的模块视图。

### Interfaces

- 数据集元信息、模型产物、评估报告、校准结果的接口还没有完全统一。
- 标签成熟、窗口切分、OOS 产物写出虽然有规则，但还没有完全抽成稳定契约。

### Research

- 当前周度重训与门禁口径已经明确，但跨模型、跨数据源、跨时期的统一比较还要继续收敛。
- 校准何时开启、何时关闭，仍然需要更稳定的大方向结论。

## 4. 使用边界

- 这份文档只保留方向性缺口，不展开到任务拆解。
- 一旦某个缺口开始进入实现阶段，应转移到 `NEXT_STEPS.md` 或专项计划文档。
