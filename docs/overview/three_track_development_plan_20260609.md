# 三线开发规划（2026-06-09）

**文档颗粒度：** `overview`  
**时间属性：** `current` / `short_term` / `planning`  
**作用：** 固定当前三条开发线的目标、边界、依赖、阶段顺序与验收标准。  
**状态：** active

## 1. 背景判断

当前项目不再按“多 worktree 多分支并行”推进。开发入口收敛到当前工作区与当前分支；三条线作为工程工作线管理，必要时再在同一工作区内切换或创建 Git 分支。

三条工作线是：

1. `3d/5d/10d` 短期预测模型线；
2. `1d` 超快速预测线；
3. 决策模型线。

2026-06-10 补充判断：

- 当前 `3d/5d/10d` 预测还不能默认视为可用交易信号；
- 决策模型可以先定义接口骨架，但不应成为第一实现优先级；
- 第一优先级应切换为建立可信评估范式、排除伪信号、形成主线预测优化闭环。

这三条线不是并列堆功能，而是有明确依赖：

- `3d/5d/10d` 是当前主 alpha 候选，但必须先通过可信评估与优化门禁；
- `1d` 只有在拿到可靠日内/分钟级数据后才有继续建模价值；
- 决策模型消费预测输出、风险约束和组合状态，把分数变成可执行动作；但它不能替代上游预测可用性验证。

## 2. 总体开发原则

- 不恢复多 worktree 开发模式。
- 不让 `1d` 线污染 `3d/5d/10d` 主线默认配置、损失、报告或推荐排序。
- 不把日 K 级 `1d` 结果作为 `1d` 超短线可行性的最终判断；日 K 只能作为负对照或最低基线。
- 决策模型不直接等同于 backtest engine；它需要独立表达“为什么买、为什么不买、为什么换仓、为什么降风险”。
- 三条线共享数据、评估和协议基础设施，但产物、门禁和报告必须分线管理。

## 3. 工作线 A：`3d/5d/10d` 短期预测模型

### 3.1 目标

建立可信、可复跑、可解释的主 alpha 预测线。当前阶段不要默认认为它已经可交易，而是先证明它是否具备可用性。

候选默认输出：

- `pred_3d`
- `pred_5d`
- `pred_10d`
- `alpha_score`

其中 `alpha_score` 只有在通过评估门禁后，才成为推荐层和决策模型的默认主信号。

### 3.2 范围

In scope：

- 主线标签与 schema；
- LSTM baseline；
- XGBoost baseline；
- `pred_3d/pred_5d/pred_10d -> alpha_score` 聚合；
- 统一 OOS 窗口；
- IC / RankIC / 月胜率 / 最差月 / 连续负月 / trade-like panel；
- 预测准确度评估范式；
- 伪信号 / 泄漏 / 过拟合排查；
- 多窗口、多模型、多目标的优化闭环；
- 与决策模型的输出协议。

Out of scope：

- `1d` 模型结构、损失和报告；
- 日内数据接入；
- 真实下单或生产调度。

### 3.3 阶段

#### A0：主线口径冻结

- 确认 `trend_schema` 是主线 horizon 命名的唯一口径；
- 确认 `label_3d/5d/10d` 与 `pred_3d/5d/10d` 字段；
- 确认 `alpha_score` 聚合公式和缺头处理规则；
- 确认主线默认报告不显示 `1d` KPI。

验收：

- 同一份预测输出能稳定生成 `alpha_score`；
- 缺少任一主线头时，聚合层有明确失败/无效标记；
- 主线报告字段不依赖临时 CLI 覆盖。

#### A1：LSTM 与 XGBoost 基线闭环

- LSTM 和 XGBoost 使用同一 OOS 窗口；
- 使用同一主指标和同一报告结构；
- 明确 `baseline`、`candidate-best`、`frozen-best` 的状态；
- 禁止用不同窗口制造伪优势。

验收：

- 能回答“当前主线 LSTM 与 XGBoost 谁更稳”；
- 结果可复跑；
- 报告能进入统一比较面板。

#### A2：可信评估范式与伪信号排查

- 固化 Daily-CS IC / RankIC 与 trade-like panel 的主次关系；
- 强制检查标签成熟日、交易时点、复权口径、停牌 / 涨跌停处理；
- 引入 shuffle、time reverse、lag-1、随机标签、行业 / 市值中性化等防伪检查；
- 区分 raw / calibrated / trade-like 的解释边界；
- 建立 OOS、rolling、双窗口、近期窗口、压力窗口的比较协议。

验收：

- 高 IC 结果必须能通过防伪检查；
- 评估报告能说明“准确度来自真实排序能力、时序错位、样本选择，还是校准 / 聚合技巧”；
- 未通过可信评估前，不允许把 `alpha_score` 交给决策模型作为默认可交易信号。

#### A3：预测优化闭环

- 比较 LSTM、XGBoost 与必要时的轻量融合；
- 系统评估窗口长度、重训频率、loss 权重、rank-aware / IC-aware loss；
- 分组特征增量与消融；
- 重点压低坏月、连续负月和伪稳定性。

验收：

- 至少有一个候选模型通过可信评估门禁；
- 能明确给出 go / no-go / continue-research 判断；
- 默认参数、候选参数、冻结参数边界清晰。

#### A4：主线聚合与决策模型接线

- 输出 `alpha_score` 与三头贡献；
- 决策模型只消费稳定字段，不依赖训练脚本内部细节；
- 记录模型版本、配置版本和数据快照。

验收：

- 决策模型可以在不理解三头训练细节的前提下消费主线信号；
- 任一推荐能回溯到三头贡献和聚合版本。
- 只有通过 A2 / A3 的信号才能进入默认决策模型评估。

## 4. 工作线 B：`1d` 超快速预测与日内数据

### 4.1 目标

回答 `1d` 是否值得作为独立超短周期预测线存在。

当前关键判断：仅靠日 K 线不足以支撑高质量 `1d` 超快速预测；继续推进前必须先验证日内/分钟级数据的可得性、历史长度、字段质量和复现成本。

### 4.2 数据源初判

#### 首选候选：TuShare `stk_mins`

TuShare 官方文档显示，`stk_mins` 是 A 股历史分钟行情接口，支持 `1min/5min/15min/30min/60min`，提供 Python SDK 和 HTTP RESTful API；单次最大 8000 行，可循环按股票和时间获取，并标注可提供超过 10 年历史分钟数据，但需要单独分钟权限。

参考：<https://tushare.pro/document/2?doc_id=370>

结论：

- 适合做长期 `1d` 超短线研究候选；
- P0 必须先验证权限、覆盖率、拉取速度、费用和复权/停牌/涨跌停对齐；
- 不能默认假设已经可用。

#### 快速验证候选：AkShare 分钟接口

AkShare 官方文档中，`stock_zh_a_minute` 可获取 1、5、15、30、60 分钟频率的 A 股分时数据，但文档也标注相关分钟接口返回近期数据。`stock_zh_a_hist_min_em` 对 1 分钟数据也存在近 5 个交易日等限制说明。社区 issue 中也反馈过部分接口只能返回近 5 到 9 个交易日的 1 分钟数据。

参考：

- <https://akshare.akfamily.xyz/data/stock/stock.html>
- <https://github.com/akfamily/akshare/issues/5971>

结论：

- 适合做接口 smoke test、字段样例和近期特征原型；
- 不适合作为长期 OOS 研究的唯一历史分钟数据源；
- 如果使用 AkShare 做 P0，必须把“历史窗口不足”写进报告。

### 4.3 阶段

#### B0：日内数据可用性验证

目标不是建模，而是回答数据能不能支撑建模。

必须产出：

- 数据源对比表：TuShare / AkShare / 其他候选；
- 股票池覆盖率；
- 可获得历史长度；
- 分钟频率：1min / 5min / 15min；
- 字段：open/high/low/close/volume/amount/time；
- 缺失率和异常时间戳；
- 复权、停牌、涨跌停、集合竞价、午休断点处理方案；
- 缓存格式和增量更新策略。

验收：

- 至少一个数据源能支撑固定股票池、固定时间窗的分钟级回放；
- 否则 `1d` 建模保持 blocked，只保留日 K 负对照。

#### B1：`1d` 标签和特征协议

在分钟数据验证通过后，定义：

- next-day direction；
- open-to-open / close-to-next-open / intraday-to-next-close 等标签；
- 日内特征聚合窗口，如开盘 30 分钟、上午、尾盘、全天；
- 严格避免使用目标日未来信息。

验收：

- 标签成熟规则明确；
- 分钟特征只能使用预测时点之前可见的数据；
- 可生成训练/验证/测试切分。

#### B2：最小模型验证

顺序固定：

1. XGBoost + `1d direction`
2. LSTM + `1d direction`
3. Transformer 后置，仅当前两者证明值得继续

日 K-only baseline 只作为对照，不作为 go/no-go 的唯一依据。

验收：

- 独立报告回答 go / no-go；
- 明确收益是否覆盖噪声、换手和成本；
- 不并入主线 `alpha_score`。

## 5. 工作线 C：决策模型

### 5.1 目标

把预测分数变成可审计的交易决策链。

当前阶段的约束：如果 `3d/5d/10d` 预测未通过可信评估门禁，决策模型只能推进接口、日志和规则骨架；不能用未验证信号制造“可交易闭环”的错觉。

决策模型的输入不是单一预测分数，而是：

- 主线 `alpha_score`；
- 三头贡献；
- 可选的 `1d` 独立信号；
- 当前持仓；
- 交易成本；
- 风险状态；
- A 股交易约束；
- 市场可交易性状态。

输出必须是：

- target positions；
- orders 或 no-trade decision；
- risk checks；
- action reason；
- blocked reason；
- diagnostics。

### 5.2 阶段

#### C0：决策输入/输出协议冻结

- 冻结决策模型输入字段；
- 冻结决策输出字段；
- 明确 `alpha_score` 是默认主信号；
- `1d_signal` 只能作为可选旁路输入，默认缺省。

验收：

- 可以用固定 CSV/Parquet 输入复跑同一组决策；
- 输出能解释每个买入、卖出、持有、不交易原因。

#### C1：换仓门槛与成本覆盖

- 仅当新候选显著优于当前持仓才换仓；
- 仅当预期边际收益覆盖成本才交易；
- 记录 `rebalance_threshold_blocked` 与 `cost_coverage_blocked`。

验收：

- 换手下降或成本占比改善；
- 收益不因过度过滤显著失真；
- 每次不交易有结构化原因。

#### C2：风险禁买与成交阻断诊断

- 接入 `risk_buy_disabled`；
- 区分 T+1、涨跌停、停牌、现金不足、风险禁买；
- 输出 daily diagnostics。

验收：

- 回测摘要能统计各类阻断原因；
- 不再只有净值结果而无法解释动作。

#### C3：组合约束与决策学习

在 C0-C2 稳定后，再考虑更复杂的决策模型：

- 最小持有期；
- 最大持仓数；
- 行业/主题暴露；
- 现金下限；
- regime-aware sizing；
- learning-to-rank 或 policy model。

验收：

- 新决策模型必须优于规则基线；
- 必须在固定主线信号输入下比较，不能混入上游模型变化。

## 6. 三线依赖关系

```text
3d/5d/10d 主线预测
        |
        v
    alpha_score --------------+
                               |
1d 日内数据 -> 1d 独立信号 ----+--> 决策模型 -> target_positions / orders / diagnostics
                               |
当前持仓 / 成本 / 风控 --------+
```

关键规则：

- 决策模型可以先用主线 `alpha_score` 推进，不等待 `1d`。
- `1d` 不能绕过数据可用性验证直接进入模型扩张。
- 主线预测不能因为决策模型需要更多字段而破坏现有报告边界。

## 8. 分支与工作区策略

当前默认：

- 单 worktree；
- 当前分支作为开发入口；
- 不自动创建新分支；
- 不恢复旧的多 worktree 并行。

如后续需要 Git 分支隔离，建议命名：

- `feature/model-3510d-mainline`
- `feature/model-1d-intraday`
- `feature/decision-model`

但这些只是建议名，不代表当前已经创建或要求立即创建。

## 9. 当前不做

- 不把 `1d` 并入主线 `alpha_score`；
- 不用日 K-only `1d` 结果否定或证明超短线方向；
- 不在 `3d/5d/10d` 未通过可信门禁前，把复杂决策模型实现当作第一优先级；
- 不在决策模型未有规则基线前上复杂 RL/policy model；
- 不用新增数据源绕过泄漏、复权、停牌、涨跌停和交易时点校验；
- 不为了并行感重新制造多 worktree。
