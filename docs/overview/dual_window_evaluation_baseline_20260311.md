# 双窗口评估基线（2026-03-11）

## 1. 目的

本文档用于统一主模型线与 `1d` 研究线的评估窗口协议，解决以下问题：

- 当前实验容易只看单一时间窗，导致可比性和近期有效性混在一起；
- `develop`、`1d` 分支后续都要推进 baseline，但缺少统一外层时间边界；
- 不同实验若各自选窗，很容易制造伪优势。

本文档冻结一个“双窗口评估基线”：

1. 固定基准窗口：负责横向可比；
2. Latest 滚动窗口：负责近期有效性。

---

## 2. 结论

后续主模型与 `1d` 研究默认都应记录 `evaluation_window_id`，当前冻结两类窗口：

- `fixed_20230101_20250701`
- `latest_rolling`

两者缺一不可：

- 只跑固定窗口，不足以说明近期还能不能用；
- 只跑 Latest 窗口，不足以做稳定横向比较。

---

## 3. 固定基准窗口

## 3.1 窗口 ID

`fixed_20230101_20250701`

## 3.2 时间边界

- 起始日期：`2023-01-01`
- 结束日期：`2025-07-01`

说明：

- 这里指的是该轮实验的固定原始数据覆盖边界；
- 在这个固定边界内，再按各模型协议执行 rolling train / valid / OOS；
- 后续若要修改这条固定窗口，必须新增新的 `evaluation_window_id`，不能直接覆盖原值。

## 3.3 角色

- 作为主模型和 `1d` 研究的共同 benchmark window；
- 用于跨模型、跨股票池、跨分支的稳定比较；
- 用于判断“某个实验是否真的优于当前基线”。

---

## 4. Latest 滚动窗口

## 4.1 窗口 ID

`latest_rolling`

## 4.2 当前冻结定义（v1）

- 截止日期：本次实验可用的最新交易日
- 覆盖长度：向前取最近 `12` 个自然月的数据

说明：

- 这里先冻结为 `12` 个月，是为了让 “Latest” 有稳定语义；
- 后续若要改成 `9` 个月或其他长度，必须通过版本或新 ID 明确升级，不能口头切换。

## 4.3 角色

- 评估模型在近期市场结构下是否仍有效；
- 避免固定长窗结果掩盖近期退化；
- 为未来更接近实盘的 baseline / challenger 判断提供依据。

---

## 5. 使用规则

## 5.1 所有 baseline 候选都应双跑

后续以下场景默认都应跑双窗口：

- 主模型 `LSTM` baseline
- 主模型 `XGBoost` baseline
- `1d` 独立研究的主候选
- 股票池切换后的比较实验

## 5.2 报告必须显式记录

每份实验产物至少应记录：

- `evaluation_window_id`
- `window_start`
- `window_end`
- `train_window_weeks`
- `valid_window_weeks`
- `test_window_weeks`
- `stock_pool_id`
- `stock_pool_version`

## 5.3 比较规则

- 固定窗口上的结果，只和固定窗口上的结果比较；
- Latest 窗口上的结果，只和 Latest 窗口上的结果比较；
- 不允许把 fixed 和 latest 的指标直接混成一个结论。

---

## 6. 对不同模型线的要求

## 6.1 `3d/5d/10d` 主线

至少要回答两件事：

1. 在 `fixed_20230101_20250701` 窗口下，当前 baseline 是否优于对照；
2. 在 `latest_rolling` 窗口下，当前 baseline 是否仍维持可接受表现。

## 6.2 `1d` 独立研究线

至少要回答两件事：

1. 在固定窗口下，`1d` 任务定义是否具备稳定统计优势；
2. 在 Latest 窗口下，这种优势是否仍存在，还是只在历史窗口里成立。

---

## 7. 与股票池基线的关系

双窗口协议必须与股票池 registry 联动使用。

也就是说：

- 比较实验时，不能只写 “Latest 上表现更好”；
- 必须同时知道它是在：
  - 哪个 `stock_pool_id`
  - 哪个 `stock_pool_version`
  - 哪个 `evaluation_window_id`
  下得出的结果。

否则结论不可复用。

---

## 8. 升级规则

以下任一变化，都必须显式升级窗口基线，不得悄悄替换：

- 固定窗口边界变化；
- Latest 窗口长度变化；
- rolling train/valid/test 外层协议变化；
- Latest 截止逻辑变化。

建议升级方式：

- 新增新的 `evaluation_window_id`
- 或在 metadata 中增加 `evaluation_window_version`

---

## 9. 第一阶段不做什么

- 不在这一轮把所有历史实验回填成双窗口；
- 不把双窗口协议和具体模型超参绑死；
- 不把 fixed 与 latest 的结果混成一个总分；
- 不在没有 `stock_pool_id` 的情况下讨论窗口表现优劣。

---

## 10. 下一步建议

1. 在 `1d` 实验协议中补 `evaluation_window_id` 的强制字段；
2. 在主模型 baseline 配置和报告中补齐窗口元数据；
3. 后续比较脚本应支持按 `evaluation_window_id` 显式输出结果。
