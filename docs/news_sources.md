# 新闻/公告数据来源（建议与注意事项）

本仓库把“新闻/公告”视为 **可插拔文本事件源**，默认不启用，避免在 V0 阶段引入时间戳不可靠与数据合规风险。

## 推荐优先级

1) **公告/正式披露文本**（优先）
   - 信息密度高、对个股影响更直接
   - 时间戳相对可靠（仍需以原始源为准）

2) **媒体新闻**（可选）
   - 噪声大、重复转载多、时间戳易混乱（穿越风险）
   - 站点 ToS/反爬与稳定性风险高

3) **社媒舆情**（不建议作为 V1 核心）
   - 数据合规与隐私风险更高
   - 噪声与操纵风险大

## akshare 相关接口（仅作备选）

akshare 提供部分新闻/公告相关函数（例如 `stock_news_em`、`stock_notice_report` 等）。

注意：
- 这些数据通常来自聚合站点，接口稳定性与授权边界需你自行评估
- 回测时必须保留原文与原始时间戳，避免把“发布后才可见”的信息用于更早日期（未来函数）

## 文本事件的最小可用落地方式（建议）

- 只做结构化抽取，不直接做“情绪打分”：
  - 事件类型：业绩预告/回购/减持/重大合同/诉讼/监管处罚…
  - 方向：利好/利空/不确定
  - 强度：金额/比例等
- 抽取器（LLM）只输出 JSON；原文必须存档，便于复核与复跑。
