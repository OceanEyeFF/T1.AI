### AI

你这个问题其实触及了 **金融机器学习里最核心的三个设计点**：

1️⃣ 多 horizon 预测（1d/3d/5d/10d）是否合理  
2️⃣ 数据如何 slice 才不会 **look-ahead bias（提前泄漏）**  
3️⃣ 实际生产中 **周末训练是否算数据泄漏**

我分别说清楚。

* * *

一、1d / 3d / 5d / 10d 多头输出会不会太多？
===============================

先说结论：

**不会，而且这是金融 ML 里非常常见的做法。**

这种叫：

**multi-horizon prediction**  
或者  
**multi-task learning**

你的结构其实像：

shared encoder  
      │  
 ┌────┼─────┬─────┬─────┐  
1d   3d    5d    10d   head

优点有几个。

* * *

1 信号在不同周期表现不同
-------------

股票信号有 **周期差异**。

例如：

特征

短周期有效

长周期有效

盘口

✔

✖

成交量

✔

✔

换手率

✔

✔

趋势

✖

✔

所以：

1d head  
3d head  
5d head  
10d head

实际上可以让模型学到 **不同时间尺度的 alpha**。

很多量化模型甚至会做：

1d  
2d  
5d  
10d  
20d

* * *

2 多任务训练能稳定模型
------------

multi-task 有个好处：

**shared representation**

例如：

encoder 学市场结构  
head 学 horizon

这样：

sample efficiency ↑  
overfitting ↓

* * *

3 但要注意两个问题
----------

### 问题1：标签高度相关

例如：

1d return  
3d return  
5d return

其实相关性很高。

所以建议：

**不要直接预测 return**

而是预测：

rank  
direction  
quantile

例如：

y1d = sign(return1d)  
y3d = sign(return3d)  
y5d = sign(return5d)

* * *

### 问题2：loss 权重

短 horizon 噪声更大。

建议：

loss =  
0.4 \* loss\_5d +  
0.3 \* loss\_10d +  
0.2 \* loss\_3d +  
0.1 \* loss\_1d

经验上：

**5d / 10d 最稳定。**

* * *

二、数据如何 slice 才不会提前泄漏
====================

金融 ML **99% 的错误都在这里**。

核心原则：

> **模型训练时只能看到预测时刻之前的数据**

形式化：

feature\_t  →  label\_t+N

例如：

X\_t = features at day t  
Y\_t = return(t → t+5)

* * *

正确数据构造
------

假设你有 2020-2024 数据。

构造样本：

date      feature         label  
\----------------------------------------  
2020-01-01  X\_1           return\_1→6  
2020-01-02  X\_2           return\_2→7  
2020-01-03  X\_3           return\_3→8

注意：

**label 一定是未来。**

* * *

Train / Test 切分
---------------

正确方式：

**按时间切**

例如：

train = 2020-2022  
valid = 2023  
test  = 2024

绝对不要：

random split

否则会产生：

**future leakage**

* * *

更专业的方式：Walk Forward
-------------------

量化常用：

train 2018-2020  
test  2021  
  
train 2019-2021  
test  2022  
  
train 2020-2022  
test  2023

这样最接近真实交易。

* * *

三、周五训练算不算数据泄漏？
==============

你说的流程是：

周五收盘  
→ 拿本周数据  
→ 训练模型  
→ 下周交易

这个：

**完全没问题。**

原因是：

预测发生在未来

具体时间轴：

Friday close  
│  
│ 训练模型  
│  
Monday open  
│  
│ 使用模型

模型没有看到未来数据。

所以：

**不算数据泄漏。**

* * *

四、真正的数据泄漏一般发生在这里
================

金融 ML 常见错误是：

### 错误1：未来 rolling

例如：

rolling\_mean\_5d

但计算方式是：

mean(t-2 ... t+2)

这就泄漏了。

正确：

mean(t-4 ... t)

* * *

### 错误2：标准化

错误：

zscore = (x - mean(all data)) / std(all data)

这使用了未来数据。

正确：

mean(train)  
std(train)

* * *

### 错误3：cross-section leakage

例如：

用当天所有股票排名

但某些股票未来会退市。

这个属于 survivorship bias。

七、本项目默认口径（2026-03-06 定稿）
===================

这一节覆盖上面的泛化讨论，作为当前仓库的正式默认配置。

### 7.1 默认输出头

- 默认基线保持为：`[3d, 5d, 10d]`
- 主评估目标保持为：`5d/10d`
- `3d` 作为辅助头保留，用于多任务正则与短周期补充
- `1d` 先不进入默认基线，只作为后续实验头

原因：

- `1d` 噪声最高，最容易放大换手与不稳定性
- 当前项目的研究门禁和评估报表主要围绕 `5d/10d` 建立
- 当前训练、评估、推荐导出链路也主要按 `3d/5d/10d` 组织

实现状态补充（2026-03-07）：

- 数据构建脚本已支持通过 `--horizons` 生成 `label_1d`（以及任意组合 horizon）。
- 当前 LSTM/XGBoost 主线训练脚本仍以固定三头实现（`label_3d/5d/10d`）为默认口径，并配套固定评估字段。
- 2026-03-10 起，主线 `3d/5d/10d` 的 schema 已集中到 `src/ashare_lab/trend_schema.py`，用于统一 horizon 顺序、`label_*` / `pred_*` 命名和 `w3/w5/w10` 权重映射。
- 因此若要上线 `d1` 输出头（含“仅预测涨跌”二分类版本），需要同步改造训练头、loss、评估报表与导出协议，而不是只改数据构建参数。

### 7.2 默认 loss 权重

当前默认建议：

- `3d/5d/10d = 0.15 / 0.45 / 0.40`

解释：

- `5d` 是当前主头
- `10d` 保留中周期信息
- `3d` 权重低于 `5d/10d`，避免短周期噪声主导训练

如果后续要试四头：

- `1d/3d/5d/10d = 0.05 / 0.15 / 0.45 / 0.35`

但这只是实验起点，不是默认生产口径。

### 7.3 默认数据切分数值

正式数据集不再推荐长期使用纯比例切分。  
默认应使用固定时间长度，避免随着数据延长而不断漂移。

默认外层切分：

- `test`：最近 `26` 周，作为 walk-forward OOS 评估区间
- `valid`：`test` 之前的 `26` 周，作为预留缓冲区间
- `train/base history`：更早的全部历史

默认滚动训练参数：

- `train_window_weeks = 104`
- `valid_window_weeks = 8`
- `calibration_weeks = 12`
- `retrain_frequency = weekly`
- `prediction_frequency = daily`

这套数值对应的现实语义是：

- 用过去约 `2` 年历史训练
- 用最近 `8` 周做滚动验证
- 用最近 `12` 周已实现 OOS 历史做校准判断
- 每周重训一次
- 下周按日推理

### 7.4 标签成熟规则

这条规则与窗口数值同等重要：

- 当前标签集合默认为 `3d/5d/10d`
- 当前主线 schema 以 `src/ashare_lab/trend_schema.py` 为单一命名入口
- 成熟门槛按最长 horizon `10d` 统一处理
- 训练、验证、校准入池条件都不能只看 `sample_date < retrain_date`
- 必须满足：样本在 `week_start` 之前已经完成 `10` 个交易日的标签计算

也就是：

- 只有 `label_maturity_date < week_start` 的样本，才允许进入本周训练池

如果没有这条规则，即使按周重训，回测仍然会偏乐观。

### 7.5 当前默认实验顺序

后续实验优先级固定为：

1. 先落实 `label maturity gate`
2. 再稳定比较 `[3d,5d,10d]`
3. 最后再比较 `[1d,3d,5d,10d]`

原因很简单：

- 如果标签成熟过滤还没落地，先加 `1d` 只会把噪声和偏差一起放大
