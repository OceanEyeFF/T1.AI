# IC评估体系改造 Prompt 包（可直接复制）

使用建议：
- 每次只用一个 Prompt，避免目标混杂。
- Prompt 里附上“必须输出文件路径 + 验证命令 + 风险点”三个约束。
- 默认要求：中文输出、先读后改、先测后结论。

---

## Prompt 1：一键执行最小改造（总控）

```text
你是本仓库的代码代理。请按 docs/LLM 研究/IC评估体系最小改造清单与计划.md 执行最小改造，严格按 Phase A -> Phase B -> Phase C 顺序推进。

硬性要求：
1) 先读取相关代码与文档，再修改。
2) 每个 Phase 完成后必须运行最小测试集并汇报结果。
3) 所有改动必须保持向后兼容（通过 label_mode/return_mode 开关）。
4) 最终输出：
   - 修改文件清单
   - 每个文件改动摘要
   - 执行过的命令及关键结果
   - 未完成项与阻塞原因

优先级：
P0 标签/验证时序一致化；P1 Daily-CS 主指标化；P2 成本后风险与 sanity check。
```

---

## Prompt 2：只做 Phase A（标签与验证口径）

```text
请仅执行 Phase A：
1) 将多周期标签改为可配置 label_mode，新增 next_open_to_open；
2) 推荐验证器收益口径改为默认 next_open_to_open，并保留 close_to_close 兼容；
3) 更新对应单元测试。

约束：
- 不改模型结构，不改训练超参，不改 unrelated 文件。
- 所有新参数必须有默认值与文档注释。

输出格式：
1) 改动文件列表
2) 关键 diff 说明（按文件）
3) 测试命令与结果
4) 剩余风险
```

---

## Prompt 3：只做 Phase B（Daily-CS + 协议门禁）

```text
请仅执行 Phase B：
1) 在 evaluation.metrics 中新增 daily-CS 计算与汇总函数（含 ICIR/t-stat）；
2) 让实验报告包含 evaluation_protocol（signal/execution/label/cost/daily_cs_mode）；
3) compare_ic_reports 增加协议一致性检查，不一致直接拒绝比较；
4) 保持现有脚本参数兼容。

输出必须包含：
- 新增字段样例 JSON
- 一条可直接运行的 strict 比较命令
- 对旧报告的兼容策略
```

---

## Prompt 4：只做 Phase C（风险指标 + 防伪信号）

```text
请仅执行 Phase C：
1) 在回测 stats 增加 ann_vol/sharpe/sortino/calmar/win_rate_daily/net_return_after_cost；
2) 新增 run_sanity_checks.py，至少包含 shuffle labels、time reverse、lag-1 三个实验；
3) 输出 machine-readable 报告（json）；
4) 增加最小测试或自检命令。

要求：
- 不做大规模重构；
- 不引入重依赖；
- 指标公式在代码注释中简要说明。
```

---

## Prompt 5：对现有实验做“可信度复核”

```text
请不要改代码，先做审计：
1) 读取最近 N 份 output/reports/*.json；
2) 按协议一致性、Daily-CS 覆盖率、月度稳定性、成本后表现、sanity check 五个维度打分；
3) 输出一张总表（通过/警告/失败）；
4) 给出每份报告的“下一步最小修复动作”。

必须引用具体文件路径与字段名，不要泛泛建议。
```

---

## Prompt 6：生成研究报告（面向决策）

```text
基于最新 strict Daily-CS 结果，生成一份“是否进入实盘候选”的研究报告。

报告结构：
1) 结论（通过/不通过/有条件通过）
2) 协议一致性检查
3) 预测质量（IC/RankIC/ICIR/月度稳定性）
4) 可交易性（成本后收益、风险指标、换手）
5) 防伪信号结果（shuffle/reverse/lag-1）
6) 决策建议（继续研究/进入小资金实盘/回炉）

要求：
- 所有结论必须对应具体数值与来源文件。
- 若证据不足，明确写“证据不足”，禁止强行下结论。
```

---

## Prompt 7：代码评审（只找问题）

```text
请对本次 IC 评估改造做代码评审，按严重级别输出问题清单：
- Critical：会导致未来数据泄露、指标误导、实盘偏差；
- Major：统计口径不稳健、兼容性风险、边界条件错误；
- Minor：可维护性与文档问题。

要求：
1) findings-first（先问题后总结）；
2) 每条问题都要有文件路径和行号；
3) 给出最小修复建议，不要大改架构。
```

---

## Prompt 8：失败重试（最小定位）

```text
当前阶段失败。请执行“最小定位”：
1) 先列出最近改动文件；
2) 仅运行失败相关最小测试；
3) 给出可复现步骤；
4) 提供 1~2 个最小修复补丁方案（含风险对比）。

限制：
- 不允许直接回滚全部改动；
- 不允许跳过测试直接宣布修复成功。
```

---

## Prompt 9：PR 描述生成（可直接粘贴）

```text
请基于当前改动生成 PR 描述，结构固定：
1) 背景与问题
2) 本次改动范围（In Scope）
3) 非改动范围（Out of Scope）
4) 关键设计决策与取舍
5) 风险与回滚方案
6) 测试与验证结果
7) 后续计划（下一阶段）

要求：
- 使用仓库真实路径和真实命令；
- 不要写“理论上”“应该”，只写已完成与可验证内容。
```
