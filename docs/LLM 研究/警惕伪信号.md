1) 先看“你的回测时序” vs “你的标签定义”是否一致（这是最常见的伪信号来源）

你在 docs/protocol.md 里把交易协议写得很清楚：

t 日收盘后产生信号

t+1 日 open 成交（次日开盘价） 
GitHub

但你现在的多跨度收益标签 MultiHorizonLabel 用的是：

forward_ret = close.shift(-h) / close - 1.0（也就是从 t 收盘价到 t+h 收盘价 的收益）
GitHub

这两者在“真实可交易”的意义上不是同一件事：

协议是：t 收盘后下单 → 用 t+1 open 成交（你根本拿不到 t close 成交价）

标签却在用：t close 作为起点

后果：只要你的特征里含有任何跟 t close 强相关的信息（比如收盘价、收盘后才完整确定的量价统计、甚至当日 close 本身），标签天然更“好预测”，IC 会被抬高。

✅ 修正建议（强烈建议你做一个“交易一致标签”版本）
如果你执行是 t+1 open，那标签最朴素的版本应该是类似：

label_h = open.shift(-(h+1)) / open.shift(-1) - 1（从 t+1 open 到 t+h+1 open）

或者从 t+1 open 到 t+h close（看你持有/平仓定义）

只要你把这个对齐做了，0.1668 的 IC 很可能会明显掉一截；掉了反而是好事：说明你把“不可交易的伪优势”挤出去了。

含成本：手续费+滑点+冲击成本；你的协议里也强调了执行约束（涨跌停/停牌等）
GitHub
